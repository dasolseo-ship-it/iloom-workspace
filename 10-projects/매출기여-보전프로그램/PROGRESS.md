3. **5% 계산 기준**

## 2026-06-22 — 선우님 미팅: 데이터 소스 전환 + 정산 방식 확정

### 의사결정 사항

| 항목 | 기존 | 변경 | 이유 |
|------|------|------|------|
| **정산 타이밍** | 월별 정산 | **행사 종료 후 3개월 뒤 1회** | 납기 확인 후 정산이 원칙 |
| **데이터 소스** | ERP 다운로드 | **태블로 로데이터** 우선 검토 | 핸드폰 뒷4자리+품목 정보 포함, ERP보다 정확 |
| **매칭 키** | 이름 + 동 | **이름 + 동 + 핸드폰 뒷4자리** | 태블로 데이터에 번호 있음 → 정확도↑ |
| **데이터 범위** | 3개월치 통째 | **행사 수주기간만** (며칠~2주) | 데이터량 대폭 감소, 다운로드 가능 |

### 검증된 사실
- 실제 테스트에서 빨간색(확정 매칭) 건들 발견 → 시스템 유의미한 결과 확인
- 태블로 데이터: 수주 1건 = 품목별 여러 행 (tidy data 구조), 핸드폰 번호 포함
- ERP 데이터: 수주 1건 = 1행 (요약형), 핸드폰 번호 없음
- 박지현 샘플 테스트: 이름+동+금액 일치 → 동일인 확인 (휴대폰 뒷4자리까지 일치)

### 확정된 정산 플로우 (최종)
```
행사 종료 → 3개월 뒤 →
  ① 태블로에서 [행사 수주기간]만 다운로드 (핸드폰+품목 포함)
  ② 시스템 업로드 → 자동 매칭 (이름+동+핸드폰 뒷4자리)
  ③ 품목 2차 검증 (인정/불인정 자동 판단)
  ④ 보전금 산정 → 지급
```
→ 데이터 push는 행사별 1회, 월별 반복 작업 없음

### 품목 인정 기준 (구체화)
| 케이스 | 인정 여부 |
|--------|----------|
| 같은 시리즈 + 같은 품목 타입 (사이즈/색상만 다름) | ✅ 인정 |
| 쿠시노 1200 ↔ 쿠시노 1400 | ✅ 인정 |
| 모션형 책상 ↔ 다리형 책상 | ❌ 불인정 |
| 옷장 ↔ 옷장 (다른 라인) | ✅ 인정 (카테고리 동일) |
| 쿠시노 ↔ 쿠시노코지 | ❌ 불인정 (기존 규칙 유지) |
| 로이 ↔ 로이모노 | ❌ 불인정 (기존 규칙 유지) |

### 현재 개발 단계 (선우님 표현)
- ✅ **페이지 1**: 동일인 찾기 (이름+동 매칭) — 완료
- 🔄 **페이지 2**: 품목 검증 자동화 (태블로 로데이터 활용) — 진행 중
- ⬜ **페이지 3**: AI 자동 품목 인정/불인정 판단 — 미래 목표
