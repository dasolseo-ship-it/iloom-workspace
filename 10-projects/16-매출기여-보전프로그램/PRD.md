# PRD — 매출기여 보전 프로그램 대시보드 v2

> 작성일: 2026-06-24 | 작성자: 서다솔 | 버전: 2.0

---

## 1. 배경 및 목적

온라인 행사로 인해 오프라인 수주가 취소되는 경우, 대리점에 고객 결제액의 5%를 보전해주는 정책(품의26-03-00266)을 시스템화한다.

**v1의 문제점:**
- 탭 구조가 기능 중심이라 처음 보는 팀원이 흐름을 파악하기 어렵다
- 행사별 데이터가 구분되지 않아 어떤 행사의 건인지 추적이 안 된다
- 수기 이의제기 건을 넣을 구조가 불명확하다

**v2의 목표:**
- 행사를 중심으로 모든 데이터와 화면을 구조화한다
- 팀원 누구나 링크만으로 접근하고, 흐름을 따라 사용할 수 있다
- 수기 이의제기 등록을 명확한 경로로 제공한다

---

## 2. 사용자 및 시나리오

| 사용자 | 역할 |
|--------|------|
| 서다솔 (담당자) | 행사 등록, 데이터 업로드, 매칭 검토, 수기 이의제기 등록, 집계 확인 |
| 팀원 | 특정 행사 결과 조회, 수기 이의제기 등록 |

**접근 방식:** 로그인 없음. 링크 공유로 누구나 접근 가능.

### 핵심 사용 시나리오

**[담당자] 행사 종료 후 정산 처리**
1. 행사 등록 (행사명, 공지일, 기간, 행사 품목, 온라인 채널)
2. 태블로에서 행사 수주기간 데이터 다운로드 → 엑셀 파일 업로드
3. 자동 매칭 결과 검토 (인정/불인정 확인)
4. 수기 이의제기 건 등록 (증빙 확인 후)
5. 보전금 집계 확인 → 엑셀 출력

**[팀원] 이의제기 등록**
1. 링크로 접속 → 해당 행사 선택
2. 수기 이의제기 탭에서 오프라인/온라인 수주번호 + 소명사유 입력

## 3. 정보구조 (IA)

```
홈 (행사 목록)
  ├── 행사 카드 목록 (진행중 / 정산완료)
  │     ├── 행사명, 기간, 현황(보전후보 N건, 집계 N원)
  │     └── 클릭 → 행사 상세
  └── + 새 행사 등록 버튼

행사 상세 (행사 선택 후)
  ├── 행사 정보 요약 (기간, 품목, 채널, 납기 기준)
  ├── Step 1: 데이터 업로드
  │     ├── 태블로 엑셀 파일 업로드
  │     ├── 업로드 현황 (전체 건수, 순수취소 N건, 납기변경 N건)
  │     └── 업로드된 데이터 목록 (수주번호, 매장, 고객명, 취소유형)
  ├── Step 2: 매칭 결과 검토
  │     ├── 자동 매칭 결과 카드 목록
  │     │     ├── 고객명 + 매칭 신뢰도
  │     │     ├── 오프라인 취소건 ↔ 온라인 재주문건
  │     │     ├── 품목 인정/불인정 결과
  │     │     └── 승인 / 반려 처리
  │     └── 수기 이의제기 등록
  │           ├── 오프라인 수주번호
  │           ├── 온라인 수주번호
  │           └── 소명사유
  └── Step 3: 보전 집계
        ├── 매장별 보전금 카드 (인정건수 / 보전금액)
        ├── 전체 집계 테이블
        └── 엑셀 출력 버튼
```

## 4. 기능 요구사항

### 4-1. 홈 — 행사 목록

| 항목 | 내용 |
|------|------|
| 행사 카드 | 행사명 / 기간 / 온라인 채널 / 상태 (진행중·정산완료) |
| 현황 요약 | 보전후보 N건 / 누적 보전금 N원 |
| 새 행사 등록 | 팝업 모달로 행사 입력 |
| 정렬 | 최신 행사 우선 |

### 4-2. 행사 등록

| 필드 | 설명 |
|------|------|
| 행사명 | 예: 2026 여름 기획전 |
| 공지일 | 커넥트플러스 공지 날짜 |
| 행사 시작일 / 종료일 | 온라인 행사 기간 |
| 온라인 채널 | 네이버 / 오늘의집 / 29CM / 쿠팡 / 에스에스지 |
| 행사 품목 | 시리즈 + 품목 조합 (복수 등록 가능) |

### 4-3. Step 1 — 데이터 업로드

- 태블로 엑셀 파일 업로드 (`.xlsx`)
- 업로드 시 자동 파싱: 수주번호 suffix(-00/-01)로 순수취소 / 납기변경 자동 분류
- 매칭 키: 고객명 + 핸드폰 뒷 4자리 (medium: 이름+동 / high: +핸드폰4자리)
- 행사와 연결: 업로드한 데이터는 해당 행사에 귀속됨

### 4-4. Step 2 — 매칭 결과 검토

**자동 매칭 결과**
- 오프라인 취소건 ↔ 온라인 재주문건 카드로 표시
- 품목 2차 자동 검증 (동일 시리즈 + 동일 품목 기준)
- 결과 상태: 인정 / 부분인정 / 불인정 / 수동검토필요
- 담당자가 건별 승인 / 반려 처리

**수기 이의제기 등록**
- 누구나 등록 가능 (로그인 없음)
- 필드: 오프라인 수주번호, 온라인 수주번호, 소명사유
- 등록 후 담당자 검토 → 수동 승인/반려 처리

### 4-5. Step 3 — 보전 집계

- 매장별 보전금 카드 (인정건수 / 불인정건수 / 보전금액)
- 전체 집계 테이블
- 엑셀 출력: 시트1 (전체 목록) + 시트2 (매장별 집계)
- 파일명: `iloom_보전금현황_행사명_YYYYMMDD.xlsx`

## 5. 정책 기준 (확정)

| 항목 | 기준 |
|------|------|
| 보전율 | 인정된 품목 금액 × **5%** |
| 수주 등록 기간 | 커넥트플러스 공지 **전일(D-1)** ~ 행사 마지막 날 |
| 납기 인정 기준 | 행사 종료일 기준 **D+1개월** 이내 납기건만 인정 |
| 정산 타이밍 | 납기 기준월 **익월 초** 일괄 처리 |
| 매칭 키 | 고객명 + 핸드폰 뒷 4자리 |
| 품목 인정 | 동일 시리즈 + 동일 품목 (사이즈·색상 차이는 인정) |
| 예외 (불인정) | 쿠시노 ≠ 쿠시노코지 / 로이 ≠ 로이모노 / 모션형 ≠ 다리형 |
| 수기 이의제기 | 담당자가 상세주소(호수) 동일 확인 후 수동 승인 |
| 데이터 소스 | 태블로 엑셀 (행사 수주기간 범위만 추출) |

## 7. v1 → v2 주요 변경점

| 항목 | v1 | v2 |
|------|----|----|
| 네비게이션 | 기능별 탭 (5개) | 행사 중심 (목록 → 행사 상세) |
